How it works

One connected workflow moves a request from the website to the local work journal without presenting separate products.

1) Website request.

The customer sends a request through the website form with the details needed for processing.

2) Server delivery queue.

The server validates the request and places it in the queue for delivery to the business.

3) Local application.

The local application receives the request, creates the working record and stores the main operational data.

4) Telegram notification.

The authorized master receives a notification and can confirm or cancel the request when that action is enabled.

5) Work status.

After the work, the request is marked completed or cancelled in the workflow.

6) Work journal and CSV.

The local journal keeps the operational record, and data can be exported manually to CSV when needed.
